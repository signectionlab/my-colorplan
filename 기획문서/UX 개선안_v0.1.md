# 컬러 교육 웹앱 UX 개선안

- 버전: v0.7
- 수정 목적: 입력 중심 화면을 시각적 실험과 결과물 중심으로 개선
- 적용 대상: 서비스 기획서(plan.md), 개발기획서, design.md
- 상태: 2단계 활동 1·2 반영. **5단계 무드보드(SVG)·3활동 점검 UI 반영(2026-10-26)**. 6단계·시작 화면 예시는 검토 중

---

## 1. 유지하는 기획

다음 사항은 변경하지 않는다.

- 교육 대상: 색채를 처음 배우는 소상공인 및 성인
- 교육 목표: 색을 배우고 자신의 브랜드 팔레트를 구성해 활용 가능한 컬러 계획 초안을 작성한다.
- 기본 기능: 색채명, 색의 상징, 대비 실습, 컬러 조합과 계획
- 프런트엔드: Svelte
- 초기 범위: DB·회원가입·로그인·결제 없이 사용
- 기본 기획서 작성: 생성형 AI 없이 템플릿 활용
- 후속 확장: 고급·유료 AI 기획 기능

배색 기준과 자유 조절의 관계 등 기존 미정 사항은 별도로 유지한다.
이번 UX 개선안으로 비율 규칙을 새로 확정하지 않는다.

---

## 2. 개선 목표

학습자가 화면에서 다음 세 가지를 쉽게 경험하게 한다.

1. 색을 바꾸면 결과가 어떻게 달라지는지 즉시 확인한다.
2. 변경 전후를 비교하며 자신의 선택을 설명한다.
3. 마지막에 시각적으로 정리된 브랜드 컬러 계획을 얻는다.

새로운 기능을 많이 추가하기보다 기존 기능의 배치와 표현을 개선한다.

---

## 3. 학습 흐름 수정

기존 6단계 구조는 유지하되 단계별 부담과 역할을 조정한다.

| 단계 | 수정 방향 |
|---|---|
| 내 브랜드 | 브랜드명 또는 사업 아이디어와 원하는 이미지를 먼저 정한다. 자세한 설명은 나중에 보완한다. |
| 내 색 이해하기 | 1단계에서 고른 색을 중심으로 관찰·톤 비교·브랜드 연결을 한다. 색 최종 확정은 하지 않는다. |
| 색 비교하기 | 배경·글자·도형 대비 실습. 구 2단계의 배경 비교 활동은 여기로 통합한다. |
| 내 팔레트 | 색·비율 조작과 결과 미리보기를 가까이 배치한다. |
| 적용과 점검 | 실제 활용 예시를 확인하고 짧은 선택과 설명으로 점검한다. |
| 계획 초안 | 시각적으로 정리된 계획서를 먼저 보여주고 항목별 수정과 내보내기를 제공한다. |

## 4. 시작 화면 개선

### 변경 내용

- 완성된 컬러 계획 예시를 추가한다.
- 예시에는 브랜드명, 이미지 키워드, 세 색과 비율, 적용 미리보기를 포함한다.
- 실제 학습자가 만들 결과물과 같은 구조를 사용한다.
- 예시임을 명확하게 표시한다.
- 실습 시작하기를 주 행동으로 유지한다.
- 작업 파일 불러오기와 백업은 보조 행동으로 배치한다.

### 완료 기준

설명을 길게 읽지 않아도 무엇을 만들게 되는지 이해할 수 있다.

## 5. 입력 부담 줄이기

### 변경 내용

- 첫 단계는 브랜드명 또는 사업 아이디어, 원하는 이미지 선택을 중심으로 구성한다.
- 상세 소개와 긴 선택 이유는 선택 입력으로 두고 나중에 보완할 수 있게 한다.
- 선택 이유는 짧은 선택지와 직접 입력을 함께 제공한다.
- 선택지는 정답이나 자동 진단이 아닌 작성 도움말로 사용한다.
- 앞 단계에서 작성한 설명을 다음 단계에서 이어받는다.
- 수정하지 않는 한 기존 기록을 유지한다.

### 선택 이유 도움말 예시

- 따뜻한 느낌이 들어서
- 글자가 잘 보여서
- 상품이나 재료와 어울려서
- 다른 색을 돋보이게 해서
- 직접 쓰기

### 완료 기준

색을 실험하기 전에 여러 개의 긴 문장을 작성할 필요가 없다.
같은 이유를 단계마다 반복해서 입력하지 않는다.

## 6. 팔레트 화면 재구성 (4단계)

### 변경 내용

- **4활동 구조**: (1) 역할 이해 카드 3장 → (2) 비율·색 조절 → (3) 적용 미리보기 → (4) 조합 선택 이유.
- 색 조합·미리보기를 중심에 두고, 조절(활동 2)과 결과(활동 3)를 데스크톱에서 나란히 배치한다.
- 짧은 한글 색 이름·역할 설명을 본문에, HEX·긴 색조명은 `details`로 이동한다.
- 색별 활용·이유와 조합 메모는 활동 4 및 `details` 보조 영역.
- **60:30:10 예시 되돌리기**와 **기준 팔레트 저장·복원**을 버튼 문구로 구분한다.
- 미리보기: 사용자 브랜드명·방향 메모·적용분야 variant; 고정 「수제 베이커리」류 제거.
- 3단계 관찰 요약은 미리보기 상단 참고 블록(자동 팔레트 반영 없음).

### 데스크톱 배치 (구현)

- 왼쪽: 활동 1·2·4
- 오른쪽 sticky: 활동 3(현재·기준 `BrandPreview`, 읽기 쉽게 보정 토글)

### 모바일 배치 (구현)

- 활동 순서 유지; 미리보기는 활동 3 카드에서 확인.

### 완료 기준

- [x] 비율 조절 중 미리보기·컬러 바가 즉시 갱신된다.
- [x] 조합 선택 이유를 선택형으로 기록할 수 있다.
- [ ] 모든 활용분야 전용 미리보기(공간·포장 등)는 단계적 추가.

## 7. 변경 전후 비교 (3·4단계)

### 추가 기능

- **3단계**: 현재 vs 기준(저장 baseline 또는 시작 예시) 이중 패널, 프리셋, 기준 저장·복원·예시 초기화.
- **4단계**: 현재 vs 기준 팔레트 `BrandPreview` + `PaletteBar`.

### 저장 내용

- 대비 실습(`compare`): 배경·글자·도형, `baseline` 스냅샷, surround 배경, 선택형 관찰 필드.
- 팔레트(`palette`): 세 색·비율·역할, `baseline` 스냅샷, `comboReasonChoice`·`comboReason`.

실습별 기준안 하나와 현재안 하나만 지원(클라우드 이력 없음).

### 동작 원칙

- `compare`와 `palette` 상태 분리. 3단계 색 변경이 4단계에 자동 전파되지 않음.
- 기준안은 복사본; 복원 시 관찰·브랜드 메모 등 무관 필드를 지우지 않음.
- 기준 없을 때 3단계는 **시작 예시**로 비교 영역을 채움.

### 완료 기준

- [x] 기준·현재를 같은 크기로 나란히 볼 수 있다.
- [x] HEX 없이 색 선택기·칩으로 조작할 수 있다.

## 8. 적용 미리보기 개선

### 변경 내용

미리보기 종류를 늘리기보다 소수 예시의 표현을 구체화한다.

우선 대상 제안:

- 명함
- 간단한 메뉴판 또는 홍보 카드

각 예시에는 제목, 본문, 강조 정보 등 서로 다른 색의 역할을 확인할 수 있는 요소를 넣는다.

### 면적 비율과 활용 예시의 구분

- 컬러 바: 선택한 면적 비율을 정확히 표시
- 적용 미리보기: 색의 활용 위치와 인상을 보여주는 예시

미리보기의 실제 픽셀 면적이 선택 비율과 정확히 일치한다고 표현하지 않는다.

### 5단계(적용·점검) — 현재 구현 (2026-10-26)

**개선 목적:** 1~4단계 선택을 **한 분야 목업**에 적용해 보고, **객관식 중심** 3활동으로 점검한다. 무드보드는 유지하고, 하단 질문 영역만 카드·레이아웃을 개선한다.

**화면 순서**

1. 브랜드 무드보드(막대 + **1단계 선택 분야** SVG 1장)
2. 활동 1 — 브랜드 이미지 확인
3. 활동 2 — 색의 역할 이해
4. 활동 3 — 브랜드 활용 계획
5. 이전 / 다음(앱 푸터)

**무드보드**

- 5분야 **탭 없음** — `applyFieldId` 1개만.
- 2단계 PNG와 **별도** SVG(`mood-mokup-assets.md`). 업로드 없음.
- 패널 70% 너비; 구 **4장면 범례 리스트** 제거.

**활동별 UX**

| 활동 | 질문·입력 | 색 표현 |
|------|-----------|---------|
| 1 | 1단계 키워드/픽 + Q1 3지선다 + 핵심 색 1개 | `ReviewPaletteColorRow` 칩 |
| 2 | 팔레트 요약 + 주조 역할 1문항 + 학습 한 줄 | 동일 칩 행 |
| 3 | 색별 활용 위치 **칩 다중 선택** + 이유 객관식(직접 입력) | 행마다 칩 |

**원칙**

- 1~4단계 데이터 자동 로드; 선택 즉시 저장(JSON).
- 긴 textarea 연속 배치 지양(활동 3 위치는 선택형).
- 「다른 느낌」 등 → 4단계 이동.
- 활동 3 → 6단계 「활용 위치」「활용 이유」 반영.

**면적 vs 목업**

- `PaletteBarSegments` = 사용자가 정한 **비율·역할**.
- 목업 SVG = **역할·분위기** 확인용(픽셀 % = 막대 % 아님, 특히 space는 고정 HEX 매핑).

### 글자색 보정

다음 상태를 구분한다.

1. 선택한 색으로 보기
2. 읽기 쉽게 보정해서 보기

보정 시 사용한 색과 변경 사실을 표시한다.
팔레트에 없는 색을 조용히 추가하지 않는다.
보정이 원래 팔레트를 자동 변경하지 않게 한다.

### 완료 기준

학습자는 자신의 선택 결과와 자동 보정 결과를 구분할 수 있다.

## 9. 내 색 이해하기 화면 개선 (2단계)

### 변경 목표

1단계 선택과 2단계 학습이 끊기지 않게 한다. 사용자 브랜드 색을 화면의 중심 시각 요소로 두고, 한 번에 하나의 관찰 활동에 집중하게 한다.

핵심 질문: **내가 고른 색은 어떤 특성을 가지고 있으며, 우리 브랜드에 어떤 인상을 줄 수 있을까?**

안내 문장: **1단계에서 선택한 색을 살펴보고, 브랜드에 어울리는 이유를 찾아보세요.**

### 화면 구조 (현재 구현)

1. 브랜드 맥락 카드 — 브랜드명, (있을 때) **1단계에서 선택한** 활용 분야 참고 이미지, **전달하고 싶은 방향**(`keywordReason`). 1단계 분야 선택 UI에는 참고图 없음.
2. **pick-row** — 1단계 브랜드 색 3~5개(색명·톤·HEX). **활동 1** 전용 선택(`focusPickKey`), primary 테두리·`aria-pressed`
3. **활동 1** (`STEP 2 · 활동 1`) — hero 카드(이미지 형용사), 색 이름 표, 밝기/비슷한 톤 탭
4. **활동 2** (`STEP 2 · 활동 2`) — 전체 pick 대상, UI 포커스 `act2PickKey`(활동 1과 분리)
   - **이중 게이지 네비**: 1단계 HEX(고정) / 비교 후 선택(동적). 선택완료 열 아랫줄 **✓**. 게이지 테두리 없음(밝은 무채 hairline만)
   - **색을 고른 이유** 블록(있을 때)
   - 비교 톤 칩(후보 2개 이상일 때) → **내가 고른 색** / **비교할 색** 카드 + 동일 2지선다 라디오. **미선택 허용**, **「아직 잘 모르겠어요」 UI 없음**(레거시 `unsure` 저장값은 유지)
5. ~~활동 3 · fit/이유~~ — LearnScreen에서 제거(데이터·계획서 호환)
6. ~~보조 다른 색 살펴보기~~ — LearnScreen에서 제거(`interestIds` 호환 유지)

### 이 단계에서 하지 않는 것

- 배경·글자 대비 실습 → 3단계 「색 비교하기」
- 세 색 팔레트·비율 확정 → 4단계 「내 팔레트」

### 콘텐츠·표현 원칙

- HEX·톤 칩은 UI 근사값임을 구분해 표기한다. 표준 측색을 주장하지 않는다.
- `provisional` 임시 교육 문구는 「예시」로 분리하고 확정 사실처럼 쓰지 않는다.
- 색이 특정 감정을 반드시 유발한다고 단정하지 않는다.
- 활동·이유 입력을 생략해도 다음 단계로 갈 수 있다.

### 보조 탐색(다른 색 살펴보기) — 후속

- 현재 LearnScreen에는 미포함. `learn.interestIds` / `reasons`는 JSON·4단계에서 호환.
- 재도입 시: 메인에 긴 전체 색 목록 금지, 탭·예시 콘텐츠 일치, `colors.ts` adjective 탭과 활동 1 계통색명 혼동 방지(color-data.md 참고).

### 저장

- `learn.focusPickKey` — 활동 1
- `learn.brandPickRecords` — `imageCompareSide`, `compareToneId`, (레거시) `fitChoice`, `fitReason`
- `interestIds` / `reasons` — 필드 유지, 2단계 UI 없음
- JSON v2 호환, `learn-normalize` merge

### 완료 기준

- [x] 1단계에서 고른 색이 pick-row·활동 2 게이지에 정확히 보인다.
- [x] 활동 1 포커스와 활동 2 비교 색 전환이 분리된다.
- [x] 1단계 색과 비교 후 선택을 이중 게이지로 직관적으로 비교할 수 있다.
- [x] **색을 고른 이유**가 톤 비교 맥락에 노출된다.
- [x] 톤 비교를 일부만 해도 다음 단계로 이동할 수 있다.
- [x] 기록이 pick 키에 맞게 유지되고, 새로고침·JSON 불러오기 후에도 남는다.

## 10. 색 비교하기 화면 개선 (3단계)

### 변경 목표

배경·글자·주변색 관계를 **관찰 활동**으로 재구성한다. HEX 중심 UI를 줄이고, 선택형 관찰로 학습 결과를 4단계·계획서에 연결한다.

핵심 질문: **색을 함께 사용하면 어떻게 보일까요?**

## 12. 최종 계획서 화면 개선

### 변경 내용

기본 화면을 마크다운 편집창에서 시각적인 계획서 미리보기로 변경한다.

### 표시 순서

1. 브랜드명과 소개
2. 의도한 이미지 키워드
3. 2단계 색 이해·선택 이유(기록이 있을 때)
4. 3단계 대비·관찰(선택형·메모)
5. 세 색과 색 코드
6. 역할과 사용 비율·조합 선택 이유
7. 적용 미리보기
8. 색별 활용·선택 이유
9. 점검·수정 메모

### 편집 방식

- 수정 가능한 항목에 편집 기능을 제공한다.
- 색과 비율은 팔레트 데이터를 기준으로 표시한다.
- 생성 문장과 사용자가 수정한 내용을 구분해 관리한다.
- 색 변경 시 이전 초안이라는 안내를 유지한다.
- 재생성 과정에서 사용자의 편집 내용을 무단으로 덮어쓰지 않는다.

### 내보내기

기존 기능을 유지한다.

- 내용 복사
- Markdown 다운로드
- JSON 작업 파일 보관

화면 미리보기와 내보내기가 같은 최종 데이터를 사용하도록 한다.

### 완료 기준

학습자는 코드나 마크다운 문법을 읽지 않고도 자신의 컬러 계획을 확인하고 수정할 수 있다.

## 13. 디자인 원칙 보완

### 한글 가독성

다음 값을 출발점으로 실제 화면에서 검토한다.

- 본문: 16px, 굵기 400
- 주요 질문과 레이블: 본문보다 명확한 굵기
- 보조 설명: 읽을 수 있는 크기와 대비 유지

기존 영문 디자인 가이드의 굵기 300을 모든 한글 본문에 일괄 적용하지 않는다.

### 시각적 위계

- 현재 해야 할 활동을 가장 먼저 보여준다.
- 조절 기능과 결과를 설명보다 우선한다.
- 상세 규칙은 펼쳐 보기로 제공한다.
- 모든 내용을 동일한 카드 형태와 강도로 표시하지 않는다.

### 색 사용

- 시작 화면의 브랜드 장식과 실습 화면의 색 판단 영역을 구분한다.
- 색 비교 영역 주변은 중립적인 배경을 우선한다.
- 사용자 팔레트가 화면에서 가장 중요한 색 정보가 되게 한다.

### 이동 버튼

일반적인 ‘다음’ 대신 다음 행동을 표시한다.

예:

- 내 색 이해하기
- 색 비교하기
- 내 팔레트 만들기
- 적용 결과 확인하기
- 계획서 확인하기
