## 1. 서비스 목적

> 학습자가 색을 배우면서 자신의 브랜드 팔레트를 만들고, 수정과 비교를 거쳐 활용 가능한 컬러 계획으로 발전시키도록 돕는다.

색채를 처음 배우는 사람이 자신의 브랜드에 어울리는 색을 탐색하고,
색과 비율을 직접 조절하며, 선택 이유와 활용 방법을 설명할 수 있도록 지원하는 실습형 교육 웹앱이다.

학습자는 다음 과정을 경험한다.

1. 전달하고 싶은 브랜드 이미지를 정한다.
2. 1단계에서 고른 색의 특성을 관찰하고 브랜드 이미지와 연결한다.
3. 색과 배색 비율을 바꾸며 차이를 확인한다.
4. 변경 전후를 비교하고 선택 이유를 정리한다.
5. 실제 활용 예시를 점검한다.
6. 자신의 브랜드 컬러 계획 초안을 완성한다.

서비스의 핵심은 학습자의 선택과 수정 과정이다.
자동 작성 기능은 학습자가 만든 결과를 정리하는 역할을 한다.

### 1.1 대상

- 색채를 처음 배우는 소상공인 및 성인
- 자신의 브랜드를 구체화하려는 예비 창업자
- 전문 디자인 도구를 배우기 전에 컬러 방향을 정하고 싶은 사람
- 자신의 비즈니스에 컬러 디자인을 직접 설계하고 싶은 사람(소상공인, 1인사업자 등)
- 컬러 속성, 컬러 심리를 활용한 비즈니스 아이템을 만들고자 하는 사람
- 디자이너 없이 컬러아이덴티티를 설정하고 싶은 사람

### 1.2 해결하려는 어려움

- 원하는 분위기를 구체적인 색으로 표현하기 어렵다.
- 함께 사용할 색과 비율을 정하기 어렵다.
- 색을 실제 매장, 상품, 명함, 홍보물에 적용하기 막막하다.
- 선택 이유와 활용 기준을 다른 사람에게 설명하기 어렵다.

### 1.3 최종 학습 결과

학습자는 자신의 결과물을 보며 다음 내용을 설명할 수 있어야 한다.

“우리 브랜드는 이런 이미지를 전달하고 싶어서 이 색들을 골랐고,
각각 이런 역할과 비율로 사용하겠습니다.”

최종 결과물의 명칭은 ‘브랜드 컬러 계획서’로 통일한다.
결과물은 학습자가 검토하고 수정하는 초안으로 제공한다.

## 2. 초기 서비스 범위

### 2.1 핵심 기능

| 기능 | 학습자가 하는 일 |
|---|---|
| 내 색 이해하기 | 1단계에서 고른 색의 톤·밝기 등을 관찰하고 브랜드 키워드와 연결한다. |
| 색 이름·용어 탐색 | 활동 1 표·계통색명 등으로 용어를 익힌다. (구 2단계 「다른 색 살펴보기」 탭 UI는 현재 미포함) |
| 대비 실습 | 배경·글자·도형의 색을 바꾸며 보임과 인상을 비교한다. |
| 팔레트와 계획서 작성 | 세 색의 역할과 비율을 구성하고 활용 계획을 정리한다. |

### 2.2 초기 버전에 포함하는 기능

- 시작 화면의 완성 결과물 예시
- 브랜드 이미지와 1단계 색·톤 선택
- 2단계: 선택 색 중심 관찰(활동 1)·톤 비교(활동 2) 및 색별 비교 결과 기록
- `learn.interestIds` / `reasons`(비교해 보고 싶은 색)는 JSON 호환만 유지(4단계 UI 없음, v2.7)
- 배경·글자·도형의 대비 실습
- 세 색 선택과 비율 조절
- 비율에 따른 역할 변경 표시
- 변경 전후 비교
- 적용 미리보기와 학습 점검
- 템플릿 기반 계획서 작성
- 시각적인 계획서 확인과 항목별 편집
- 브라우저 자동 저장
- 내용 복사와 Markdown 다운로드
- 브라우저 인쇄(화면의 「PDF로 저장」). 별도 PDF 생성 엔진은 없음
- JSON 작업 파일 내보내기와 불러오기

### 2.3 초기 버전에서 제외하는 기능

- 서버 DB와 클라우드 작업 보관
- 회원가입과 로그인
- 결제와 회원 등급
- 생성형 AI API를 이용한 맞춤형 계획서
- 강사 관리 화면과 학습자 관리
- 복잡한 디자인 편집기
- 자동 메일 발송
- 여러 프로젝트의 이력 관리
- 교안과 사용설명서 제작

기본 버전만으로도 학습과 계획서 완성을 끝낼 수 있어야 한다.

## 3. 학습 경험과 디자인 원칙

### 3.1 조작과 결과를 먼저 보여준다

- 색을 선택하거나 비율을 바꾸면 결과를 즉시 보여준다.
- 조절 영역과 미리보기를 가까이 배치한다.
- 상세 설명과 긴 입력은 필요한 시점에 펼쳐 볼 수 있게 한다.
- **컬러 칩 hairline(공통)**: 흰·거의 무채 밝은색 칩·스와치는 항상 `{hairline}` 테두리로 캔버스와 구분한다. 판정·마크업·CSS는 `design.md` **§ 컬러 칩 hairline (공통)**, 구현은 `needsPickSwatchHairline` + `global.css` `.color-chip.light`.

### 3.2 입력 부담을 줄인다

- 시작부터 긴 브랜드 소개와 선택 이유를 요구하지 않는다.
- 짧은 선택지와 직접 입력을 함께 제공한다.
- 앞 단계에서 작성한 내용은 다음 단계와 계획서에서 이어받는다.
- 같은 내용을 반복해서 작성하게 하지 않는다.
- 작성하지 않은 설명은 나중에 보완할 수 있게 한다.

선택 이유 도움말 예시:

- 따뜻한 느낌이 들어서
- 글자가 잘 보여서
- 상품이나 재료와 어울려서
- 다른 색을 돋보이게 해서
- 직접 쓰기

도움말은 정답이나 자동 진단이 아니다.
학습자가 선택하거나 수정한 내용만 기록한다.

### 3.3 비교를 통해 선택하도록 돕는다

- 기준안과 현재안을 함께 보여준다.
- 처음 정한 이미지 키워드를 실습 중에도 확인할 수 있게 한다.
- 차이를 관찰하고 다시 수정할 수 있게 한다.
- 근거 없는 조화 점수나 브랜드 적합성 점수를 제공하지 않는다.

### 3.4 선택과 기록을 보존한다

- 이전 단계로 돌아가도 작업을 유지한다.
- 색의 역할이 바뀌어도 해당 색의 기록을 유지한다.
- 계획서를 다시 생성할 때 직접 편집한 내용을 바로 덮어쓰지 않는다.
- 복원이나 불러오기처럼 현재 작업을 대체하는 동작은 범위를 안내한다.

### 3.5 색을 판단하기 좋은 화면을 만든다

- 실습 영역 주변은 중립적인 배경을 우선한다.
- 사용자 팔레트가 가장 중요한 색 정보가 되게 한다.
- 장식 색과 그라데이션이 색 비교를 방해하지 않게 한다.
- 색만으로 상태를 전달하지 않고 이름·숫자·텍스트를 함께 사용한다.

### 3.6 한글 가독성과 조작성을 확보한다

- 본문은 16px, 굵기 400을 출발점으로 검토한다.
- 주요 질문과 레이블은 본문보다 명확하게 구분한다.
- 보조 설명도 충분한 크기와 대비를 유지한다.
- 키보드로 주요 기능을 사용할 수 있게 한다.
- 슬라이더에는 현재 값과 숫자 입력 등 정밀 조절 수단을 제공한다.
- 모바일 고정 영역이 입력창과 조작 버튼을 가리지 않게 한다.

## 4. 전체 이용 흐름

시작 화면 이후 다음 여섯 단계로 구성한다.
단계 간 이동과 재수정을 허용하고 작성 내용을 유지한다.

| 단계 | 핵심 활동 | 남기는 결과 |
|---|---|---|
| 1. 내 브랜드 | 브랜드 또는 사업 아이디어와 원하는 이미지 정하기 | 브랜드 맥락과 이미지 키워드 |
| 2. 내 색 이해하기 | 1단계 선택 색 관찰·톤 비교·브랜드와의 연결 점검 | 색별 관찰·fit 선택·선택 이유(선택), 비교용 색 메모 |
| 3. 색 비교하기 | 배경·글자·도형 조합을 관찰하고 기준안과 비교하기 | 실습용 색, 기준 스냅샷, 선택형 관찰 응답 |
| 4. 내 팔레트 | 주조·보조·강조 역할과 비율을 설계하고 미리보기로 확인하기 | 팔레트 색·비율·역할, 조합 선택 이유, 기준 팔레트 |
| 5. 적용과 점검 | 활용 예시와 의도한 이미지를 함께 확인하기 | 적용 위치와 점검 기록 |
| 6. 계획서 완성 | 시각적인 계획서 확인·편집·보관하기 | 브랜드 컬러 계획서 |

이동 버튼은 다음 행동을 구체적으로 표시한다.

예: ‘내 색 이해하기’, ‘색 비교하기’, ‘내 팔레트 만들기’, ‘적용 결과 확인하기’, ‘계획서 확인하기’

## 5. 화면별 기능

### 5.1 시작 화면

목적: 무엇을 만들게 되는지 먼저 이해하게 한다.

구성:

- 서비스 목적을 설명하는 짧은 문장
- 완성된 브랜드 컬러 계획 예시
- 실습 시작하기
- 저장된 작업 이어하기
- JSON 작업 파일 불러오기

완성 예시에는 브랜드명, 이미지 키워드, 세 색과 비율, 적용 미리보기를 포함한다.
실제 결과물과 같은 구조를 사용하고 ‘예시’임을 표시한다.

작업 내보내기는 작업이 있는 상태에서 제공한다.

### 5.2 내 브랜드

목적: 색을 선택할 최소한의 기준을 정한다.

우선 입력:

- 색을 사용할 대상(브랜드명·사업 아이디어 등, `brand.name`)
- 전달하고 싶은 이미지 키워드

선택 입력:

- 적용 분야
- 짧은 브랜드 소개
- 이미지 키워드를 선택한 이유

브랜드명이 확정되지 않아도 실습할 수 있게 한다.
상세 소개와 긴 이유를 작성하지 않아도 다음 단계로 이동할 수 있다.

**색 선택 UI (`BrandImagePicker`)**

- **활동 1** — `STEP 1 · 활동 1` (`global.css` `.step-badge`): `.result` 카드(제목·부제·색 선택 안내) + `.result-slots-sticky` + hue 그리드(유채색·무채색). 유채색 `.hue-tone-panel` 톤 UI에는 **step 배지 없음**.
- **선택 완료 후** — `BrandColorPlan`에 `STEP 1 · 활동 2`(주·보·강·비율). **1단계 화면에 `STEP 2` 단독 배지 없음**(2단계 LearnScreen과 구분).

### 5.3 내 색 이해하기

목적: 1단계에서 선택한 색의 특성을 관찰하고, 브랜드에 어떤 인상을 줄 수 있는지 학습자 스스로 연결한다.
이 단계는 색을 최종 확정하는 단계가 아니다. 4단계에서 팔레트를 조정한다.

핵심 질문:

- 내가 고른 색은 어떤 특성을 가지고 있으며, 우리 브랜드에 어떤 인상을 줄 수 있을까?

화면 안내:

- 1단계에서 선택한 색을 살펴보고, 브랜드에 어울리는 이유를 찾아보세요.

전제:

- 1단계에서 고른 브랜드 색 3~5개가 pick-row에 표시된다.
- **활동 1**은 pick-row에서 고른 색(`learn.focusPickKey`)에만 연동된다.
- **활동 2**는 1단계 pick 전체를 대상으로 하며, 화면 내 `act2PickKey`(로컬 UI 상태)로 비교 중인 색을 전환한다. 활동 1 포커스와 분리한다.
- 브랜드명·활용 분야·1단계 **색을 고른 이유**(`brand.keywordReason`)를 맥락으로 표시한다. `brand.keywords` 줄은 2단계 UI에 노출하지 않는다.
- 활동 카드 제목 앞 **STEP 2 · 활동 n** 배지는 `global.css`의 `.step-badge`로 통일한다.
- 표시 HEX·톤 칩은 UI용 근사값이며, KS·먼셀 표준 측색값과 다를 수 있음을 구분해 안내한다.
- 정답·오답·브랜드 적합성 점수를 제공하지 않는다.

활동 1 · 내가 고른 색 알아보기

- pick-row에서 선택한 색의 hero 카드, 기본색명·계통색명·이름·톤·HEX, 이미지 형용사(대표·보조)를 본다.
- 색상·명도·채도·색조(톤) 개념은 표의 「관찰」과 짧은 안내로 설명하되, 색 미리보기와 비교가 먼저다.
- 탭 **밝기 비교** / **비슷한 톤**: `brightnessVariants`(근사), `neighborToneSwatches`(같은 계열 톤·명도 칩).

활동 2 · 색이 전하는 이미지 비교하기

- **한눈에 보기(`act2-color-nav`)**: 열마다 동일 형태 게이지 2줄 — 윗줄 **1단계에서 고른 색**(고정 HEX), 아랫줄 **비교 후 선택**(`compareChoiceGaugeForPick`: `mine` → 1단계 HEX, `other` → `compareToneId` 톤 HEX, 미선택·`unsure` 저장값 → `—`). 게이지 막대에는 테두리 없음(밝은 무채는 공통 `color-chip` hairline). 톤 비교를 마친 열은 아랫줄에 **✓**. 열 상태: **비교 중** / **선택완료** / **미탐색**(`imageCompareSide !== null`이면 선택완료).
- 같은 계열 **비교할 톤** 후보 3~4개(`compareToneCandidateIds`); 복수일 때 톤 칩으로 `compareToneId` 변경 가능(변경 시 해당 색의 `imageCompareSide`는 초기화).
- **내가 고른 색** vs **비교할 색** 카드와 라디오 **두 가지만** 제공한다. 처음에는 `imageCompareSide: null`(미선택)을 허용한다. **모든 색을 비교하지 않아도** 다음 단계로 이동할 수 있다.
- 1단계에 **색을 고른 이유**가 있으면 활동 2 상단에 노출해 톤 선택 맥락으로 쓴다.
- 관찰·인지 안내(`IMAGE_COMPARE_PERCEPTION_NOTE`)를 함께 보여 준다. 정답·브랜드 적합성 점수는 없다.
- 톤 비교 예시를 만들 수 없는 pick(일부 무채·예외)은 안내 문구만 표시한다.
- 색이 특정 감정을 반드시 유발한다고 단정하지 않는다.

**화면에서 제외된 항목(저장·호환 유지)**

- 구 **활동 3 · 내 브랜드와 연결해 보기** UI(fit / unsure / explore, 선택 이유 입력)는 LearnScreen에서 제거했다. `brandPickRecords`의 `fitChoice`, `fitReason` 및 기존 JSON 값은 merge·계획서·초안 템플릿에서 그대로 읽는다.
- 구 **보조 · 다른 색 살펴보기**(`details` 탭·「비교해 보고 싶은 색」 UI)는 LearnScreen에서 제거했다. `learn.interestIds`, `learn.reasons` 필드는 JSON 호환만 유지한다(4단계 interest 칩·「더 조정하기」 미구현, v2.7).
- 활동 2 비교 결과 `imageCompareSide: 'unsure'`는 **새 UI에서 선택할 수 없다**. 과거 저장값은 normalize·PlanScreen·초안에 반영 가능하다.

5.3에서 하지 않는 것:

- 배경·글자 대비 실습 → 5.4 색 비교하기(STEP 3)에서 수행한다.
- 세 색 팔레트·비율 최종 확정 → 5.5 내 팔레트(STEP 4)에서 수행한다.

저장(작업 상태 `learn`):

- `focusPickKey`: 활동 1에서 자세히 본 브랜드 색(`hueId:toneId`)
- `brandPickRecords` (pick 키별):
  - `imageCompareSide`: `null` | `mine` | `other` | `unsure`(레거시)
  - `compareToneId`: 활동 2 비교에 쓴 상대 톤 ID
  - `fitChoice`, `fitReason`: 레거시·계획서용(현재 2단계 UI 미편집)
- `interestIds` / `reasons`: 비교해 보고 싶은 색(2단계 UI 없음, JSON·4단계 호환)
- 도메인: `learn-brand-pick.ts`(`compareToneOptionsForPick`, `compareChoiceGaugeForPick`, `resolveCompareToneId` 등), `learn-normalize.ts`

활동을 생략해도 다음 단계로 이동할 수 있다.

### 5.4 색 비교하기

핵심 질문: **색을 함께 사용하면 어떻게 보일까요?**

목적: 배경·글자·도형의 관계를 이해하고, 조합에 따라 가독성과 인상이 어떻게 달라지는지 관찰한다.
(구 2단계에 있던 배경·글자 대비 실습은 이 단계 전담이다.)

화면 안내:

- 배경과 글자의 색을 바꿔 보세요. 어떤 조합이 더 잘 보이고, 어떤 분위기를 만드는지 비교할 수 있어요.

전제:

- 이 단계의 색(`compare`)은 **4단계 브랜드 팔레트(`palette`)와 별도**로 저장한다. 실습에서 색을 바꿔도 팔레트 원본을 덮어쓰지 않는다.
- 3단계를 완료했다고 실습 색을 팔레트에 자동 반영하지 않는다.
- 정답·브랜드 적합성 점수·근거 없는 접근성 “합격” 표현을 하지 않는다.
- WCAG 대비 계산은 규칙 기반으로 유지하되, 수치와 짧은 해석 문장을 함께 보여 준다. 수치가 높다고 더 아름답거나 브랜드에 적합하다고 단정하지 않는다.
- 주 조작은 **1단계 브랜드 색 컬러칩**과 실시간 미리보기이다. (구 프리셋·ColorPicker·HEX 입력 UI는 제거)

활동 1 · 글자·배경 비교하기 (배지: 가독성)

- 큰 빌보드가 먼저다. STEP 1 `brand.imagePicks` 칩은 **배경** 줄과 **글자** 줄로 나뉜다. 한 줄의 칩은 그 대상만 바꾼다.
- 글자 줄 옆 **웹 본문 기본색** 2개: `#333333`, `#ffffff`(라벨 둘 다 「기본」). 브랜드색이 잘 안 보일 때 쓰는 선택이다(`COMPARE_DEFAULT_WEB_TEXT_OPTIONS`).
- **용어(확정 팔레트가 아님)**: 1~3단계는 색을 **고르고 관찰하는 과정**이다. UI에서는 「브랜드 색 확정」 표현을 쓰지 않고 **1단계에서 고른 색**, **지금 미리보기**, **비교 기준**, **시작 제안**을 쓴다.
- 첫 진입 시드(`brandCompareSeedFromPicks`): 배경 = pick 첫 색, 글자 = `#333333`, 도형 = 두 번째 pick(없으면 첫 색). pick이 없으면 데모 `COMPARE_START_EXAMPLE`.
- 나란히 비교는 `details` **나란히 비교 · 관찰 기록**(기본 펼침) 안이다. 왼쪽 **지금 미리보기**, 오른쪽은 저장 전 **시작 제안** / 저장 후 **비교 기준**.
- **비교 기준으로 남기기**: 지금 미리보기의 배경·글자·shape를 `compare.baseline` 스냅샷으로 저장.
- **비교 기준 → 미리보기에 적용**: `baseline`을 지금 미리보기(`compare.background/text/shape`)에 복사. 오른쪽 칸은 바꾸지 않음. `baseline` 없으면 비활성.
- **1단계 시드로 되돌리기** 버튼은 두지 않는다.
- 미리보기 문장: STEP 1 **브랜드명**. WCAG 대비는 빌보드 아래 참고 캡션(합격·불합격 단정 없음).
- **관찰 선택 UI 없음**. `readabilityChoice`·`surroundChoice`·`brandExperimentChoice`·`observationDetail`은 JSON·이전 작업 호환만.

활동 2 · 주변 색에 따른 차이 관찰하기 (배지: 주변색 효과)

- 배경 A / B 패널에 같은 도형을 올려 비교한다.
- 브랜드 색 칩으로 **도형**(`surroundShape`), **배경 A**, **배경 B**를 각각 바꾼다. A와 B에 같은 색은 고를 수 없다.
- `surroundChoice` 라디오는 화면에 없다. 필드는 JSON 호환만 유지한다.

**화면에서 제외**: 구 활동 3 「내 브랜드 색으로 실험하기」. `brandExperimentChoice` 필드는 JSON·계획서 호환만 유지.

저장(작업 상태 `compare`):

- `background`, `text`, `shape`, `baseline`, `readabilityChoice`, `surroundChoice`, `brandExperimentChoice`, `observationDetail`, `observation`, `surroundBgA`, `surroundBgB`, `surroundShape`

4단계에서는 위 관찰을 **참고용**으로만 표시하며, 팔레트·비율을 자동 결정하지 않는다.

활동을 생략해도 다음 단계로 이동할 수 있다.

### 5.5 내 팔레트

핵심 질문: **어떤 색을 어떤 역할로, 얼마나 사용하면 좋을까요?**

목적: 주조색·보조색·강조색을 구성하고, 사용 비율에 따른 시각적 변화를 확인한다.

화면 안내:

- 세 가지 색의 역할과 비율을 바꿔 보세요. 브랜드의 분위기가 어떻게 달라지는지 확인할 수 있어요.

전제:

- 60:30:10은 **초기 학습 예시**이며 모든 브랜드의 정답이 아님을 안내한다.
- 비율 합계 100%·0% 미사용·역할 계산은 기존 `domain` 규칙을 따른다.
- 화면에는 짧은 한글 색 이름을 우선하고, KS·HEX는 카드 `details`에서 확인한다.
- 미리보기에 **사용자 브랜드명**과 방향 메모를 쓰며, 고정 예시 상호(예: 수제 베이커리)를 표시하지 않는다.
- 적용분야에 맞는 미리보기 variant를 우선하고, 미지원 분야는 공통 예시와 안내 문구를 사용한다.

**화면 카드 2개** — (1) **활동 1** 한 카드: 1단계 pick 참고 + 색의 역할(`BrandColorPlan` readonly 또는 역할 카드). (2) **활동 2** 한 카드: `h3` 소제목으로 **비율 조절 · 미리보기**(선택 이유 UI는 MVP 보류).

활동 1 · 색의 역할 — pick **3개 이상**이면 1단계 **색채계획 게이지 읽기 전용**. pick 3개 미만이면 예시 **역할 카드 3장**. `refreshPaletteColorsFromBrandColorPlan`으로 palette.colors 동기화.

활동 2 · 비율·미리보기 — **스택 막대 경계 드래그**(슬롯 색 고정·역할 뱃지) + 프리셋 **70·20·10**(pick 3개 이상) / **60·30·10** + **미리보기 바로 아래** live 블록. 역할 문구는 슬롯 % 구간(§6.2). pick 4~5는 강조 분할 슬라이더(`accentPartRatios`). `PaletteHeroPreview`. (`comboReasonChoice`·`comboReason` UI는 MVP 보류.) 기준안 저장 안내 문구는 「5단계에서 비교」라고 되어 있으나, **현행 5단계 화면에는 baseline 막대가 없다.**

**MVP 범위(4단계, v2.7)** — 「색·기준 팔레트·메모 더 조정하기」(`details` 보조 패키지)는 **현 단계 미구현**. **「이 조합을 선택한 이유」** UI(`comboReasonChoice`·`comboReason`)도 **MVP 보류**(필드·state·계획서 연동은 후속). **「이 조합을 기준안으로 저장」**(`savePaletteBaseline`)은 MVP에 포함한다. 저장값은 JSON에 남고, **현행 5단계 화면은 baseline을 보여 주지 않는다.** JSON 필드(`palette.baseline`, 색별 `usage`·`reason`, `learn.interestIds` 등)와 state 함수는 **호환·후속**을 위해 유지한다. 슬롯 HEX 직접 편집·2단계 interest 칩·색별 활용 메모 입력(4단계 UI)은 후속.

저장(작업 상태 `palette`):

- `colors`, `ratios`, `roles`, `roleNote`, `baseline`, `comboReasonChoice`, `comboReason`, 색별 `name`·`hex`·`id`·`reason`·`usage`

5·6단계와 계획서 초안에 역할·비율·조합 이유 등이 반영된다.

데스크톱·모바일: 활동 1 카드 → 활동 2 카드 순. (구 4활동 분리·sticky 미리보기 레이아웃은 통합 후 미적용.)

역할이 바뀌어도 색 카드 **슬롯 index**와 색별 기록은 유지한다.

### 5.6 적용과 점검

목적: 1~4단계에서 고른 색·비율·분야를 **실제 브랜드 목업**에 적용해 보고, 짧은 활동으로 학습 내용을 점검한다.

**4단계 → 5단계 데이터**

- `palette.ratios`, `roles`, `accentPartRatios`, 1단계 `imagePicks`·키워드·`applyFieldId`, 브랜드명은 `store.project` 공유.
- 막대·목업 hex: 4단계와 **동일 derived** (`paletteBarSegmentsForDisplay`, `paletteRoleColors`, `paletteAccentSlotHexes`).
- 4단계 팔레트 변경 후 5단계 재진입 시 목업에 **즉시 반영** (`BrandMoodboardPanel` `$effect`).
- 4단계 **기준안**(`palette.baseline`)은 JSON·후속 UX에 유지; **현행 5단계 UI는 baseline 이중 막대 미노출**(필요 시 후속).

**화면 구성 (`ReviewScreen`) — 카드 순서**

1. **적용 결과** — 배지 `STEP 5 · 적용과 점검`, 제목 **내 브랜드 컬러 적용 결과**. 브랜드명 · 분야(없으면 「범용 목업」), `PaletteBarSegments`, `BrandMoodboardPanel`. 목업 SVG는 분야와 무관하게 **`mokup-all.svg` 1장**. 에셋: [`mood-mokup-assets.md`](./mood-mokup-assets.md).
2. **활동 1 · 브랜드 이미지 확인** — 1단계 이미지 색(칩) 또는 키워드; Q1 객관식(잘 느껴져요 / 일부만 / 다른 느낌); 선택 후 follow-up **핵심 색** 1개(팔레트 segment 칩). `brandImageFeel === 'different'` 이거나 `imageFit`에 「비율」「조절」이 있으면 **4단계에서 색·비율 수정하기**.
3. **활동 2 · 브랜드 활용 계획** — 색별 **활용 위치** 다중 선택(매장 배경, 로고, 버튼 등); **활용 이유** 객관식 + 직접 입력. 카드 안에 이전/다음 버튼은 없고, 하단 푸터로 이동한다.
4. **단계 이동** — 앱 하단 푸터(이전 / 다음). 5단계에서 팔레트 편집 UI 없음.

**화면에서 뺀 활동**

- 구 **활동 2 · 색의 역할 이해**(주조 역할 퀴즈) UI는 `ReviewScreen`에 없다. `review.primaryRoleQuiz`와 `primaryRoleQuizFeedback`은 JSON·데이터 호환만 유지한다.

**무드보드 색 입히기**

- 분야별 SVG·매장 전용 매핑표는 **현재 5단계 경로가 아니다**.
- `moodMokupSvgUrlForField`는 `applyFieldId`를 무시하고 `/images/mood-mokup/mokup-all.svg`만 반환한다.
- 칠하기는 `applyMokupAllPalette`(`mood-mokup-all-recolor.ts`). 샘플 HEX·Illustrator class를 주·보·강조1~3에 치환한다. 강조 슬롯이 비면 강조색1 hex로 2·3을 채우는 호출 측 규칙은 유지한다.
- `public/images/mood-mokup/mokup-{space|product|online|print|service}.svg`는 남아 있을 수 있으나 5단계 패널은 읽지 않는다.

**저장 (`review` + `palette.colors[].usage`)**

| 필드 | 내용 |
|------|------|
| `brandImageFeel`, `imageFit`(문장 동기) | 활동 1 Q1 |

**UI 원칙**

- 무드보드 패널 가로 70% 중앙; **4장면 범례 리스트 없음**. 제목은 「브랜드 무드보드」가 아니라 **내 브랜드 컬러 적용 결과**.

### 5.7 계획서 완성

목적: 학습 결과를 이해하고 다른 사람에게 전달할 수 있게 정리한다.

기본 화면은 시각적인 계획서다. 마크다운 원문을 편집창으로 보여 주지 않는다.

**화면 순서 (`PlanScreen`)**

1. **도구 막대** — 내용 복사, Markdown, JSON, **PDF로 저장**(브라우저 `print`).
2. **01. 완성 전 점검** (인쇄 제외) — 세 줄 체크(브랜드·색 선택 / 비율 합 100 / 5단계 적용 결과), 가이드 탭(색의 사용 면적 · 색의 역할 · 색의 대비), 결정 3지선다.
   - `keep`: 현재 색채계획을 그대로 사용 → 계획서 본문으로 스크롤.
   - `adjust_colors`: 4단계로 이동.
   - `rethink_usage`: 5단계로 이동.
3. **02. 컬러플랜 계획서** — 팔레트 막대·역할·%·HEX, 브랜드명·활용 분야(분야 참고 이미지 또는 recolor hero), 1단계 색·색을 고른 이유, 슬롯별 색 특성·**선택 이유 textarea**, 5단계와 같은 `BrandMoodboardPanel`.
4. **03. 계획서 완성하기** (인쇄 제외) — 같은 인쇄를 다시 연다.

인쇄·PDF에는 점검 카드·편집 textarea·완성 버튼이 빠지고, 본문과 **최종 점검** 문장만 남는다.

**화면에서 직접 고치는 문장**은 슬롯 **선택 이유**(`plan.fieldEdits['reason.n']`)다. 색을 고른 이유·활용 위치·메모·활용 이유는 `planView`와 Markdown에는 있으나, 현재 화면 본문에는 입력칸이 없다. 색·비율이 바뀌면 선택 이유 재검토 안내(`needsPlanFactReview`)를 띄우고, 확인 전에는 덮어쓰지 않는다.

구 `plan.text`만 있고 항목 편집이 없는 저장본은 본문 아래에 원문을 보여 주고 덮어쓰지 않는다. **새 초안으로 교체** 버튼은 현재 화면에 없다.

Markdown(`formatPlanMarkdown`) 절 순서: 브랜드 기본 정보 → 선택한 색 이미지의 목표 → 색 특성·선택 이유 → 팔레트·HEX·역할·비율 → 브랜드 무드보드 → 활용 위치·이유 → 최종 점검·메모.

제공 기능:

- 슬롯 선택 이유 편집
- 완성 전 점검과 이전 단계로 돌아가기
- 내용 복사
- Markdown 다운로드
- JSON 작업 파일 내보내기
- 브라우저 인쇄(PDF로 저장)

## 6. 비율과 역할 변경 규칙

### 6.1 교육 기준

사용자가 제시한 기준은 다음과 같다.

- 주조색: 60~70%
- 보조색: 30%
- 강조색: 10%

학습자는 게이지를 조절해 색의 사용 비율을 바꿀 수 있어야 한다.
사용 비율 변화에 따라 색의 역할도 바뀔 수 있어야 한다.

예: 처음 주조색이었던 하양의 비율을 줄이면 강조색으로 바뀔 수 있다.

### 6.2 개발 적용안 — 세부 확정 필요

보조색 30%와 강조색 10%를 고정하면 주조색은 60%가 된다.
따라서 주조색 70%를 포함하는 기준과 자유 실험의 관계는 별도로 확정해야 한다.

현재 개발 적용안은 다음과 같다.

| 항목 | 적용안 |
|---|---|
| 시작값 | 60:30:10 |
| 실험 중 합계 | 항상 100% |
| 비율 조절 | 한 색을 변경하면 나머지 두 색의 비율을 함께 조정 |
| 나머지 비율 | 가능한 경우 두 색의 기존 비율 관계 유지 |
| 역할 | 슬롯 %를 **각각** `roleForSlotRatio`로 판정. **주 51~70%**, **보 11~50%**, **강 1~10%**. **70% 초과·그 밖은 보조색** 라벨(70%로 자르지 않음). |
| 구 동률 규칙 | 「1·2번 50:50이면 둘 다 보조, 1% 차면 큰 쪽 주조」는 **현재 `assignRoles`에 없다**. 50%는 보조, 51%부터 주조. |
| 강조 상한 | pick 3개 이상이고 강조가 1색이면 3번 슬롯 **최대 10%**. pick 4~5는 강조 합 10%를 `accentPartRatios`로 나눈다(2색 각 5%, 3색 각 10/3%). |
| 역할 변경 | 조절 중 라벨이 바뀌고, `roleNote`로 짧은 문장을 남긴다. |
| 카드 위치 | 조절 중에도 슬롯 index 유지 |
| 프리셋 | **60:30:10**, pick 3개 이상이면 **70:20:10**도 제공. 기준안 저장은 별도 버튼. |
| 최소 비율 | 슬롯 **최소 1%**, 합 100%. 0%·한 색 100%는 드래그 결과로 나오지 않는다. |
| 표시 반올림 | 표시 합계도 100% 유지 |

이 구간표는 화면 규칙이다. §6.1의 교육 문장(주 60~70 · 보 30 · 강 10)을 새로 확정한 표준으로 바꾸지는 않는다.

### 6.3 해석 원칙

면적 순서에 따른 역할은 앱의 실습 규칙으로 안내한다.
실제 시각적 강조는 대비와 배치의 영향도 받는다는 점을 함께 설명한다.

색의 역할이 바뀌어도 해당 색의 고유 식별자와 선택 이유는 유지한다.
컬러 바, 미리보기, 계획서는 같은 역할 계산 결과를 사용한다.

## 7. 비교와 미리보기 동작

### 7.1 변경 전후 비교

실습별로 기준안은 최대 하나다. 현재 화면에서 나란히 보는 곳은 3단계뿐이다.

- 3단계 기준안: 배경색, 글자색, 도형색. `details` 안에서 **지금 미리보기**와 **시작 제안** 또는 **비교 기준**을 나란히 본다.
- 3단계 동작: 비교 기준으로 남기기, 다시 남기기, 비교 기준 → 미리보기에 적용. 기준이 없으면 오른쪽은 시작 제안이다.
- 4단계 기준안: 세 색·비율·역할의 복사본을 저장한다. **현재 화면은 그 기준안을 나란히 보여 주거나 되돌리지 않는다.** 5단계도 보여 주지 않는다.

기준안은 현재 작업과 분리된 복사본으로 저장한다.
현재 색을 수정해도 기준안은 바뀌지 않는다.

3단계에서 기준안을 미리보기에 적용할 때는 그 실습의 배경·글자·도형만 바꾼다.
브랜드 소개와 작성 메모 등 관련 없는 정보는 유지한다.

### 7.2 비율과 활용 예시의 구분

- 컬러 바: 선택한 면적 비율을 정확하게 표시한다.
- 적용 미리보기: 색의 사용 위치와 인상을 보여준다.

적용 미리보기의 실제 픽셀 면적이 선택 비율과 정확히 일치한다고 표현하지 않는다.

### 7.3 글자색 보정

다음 두 상태를 구분한다.

1. 선택한 색으로 보기
2. 읽기 쉽게 보정해서 보기

보정한 경우 변경된 글자색과 보정 사실을 표시한다.
팔레트에 없는 색이 사용되면 추가된 색임을 알린다.
보정은 원래 팔레트를 자동 변경하지 않는다.

대비 안내는 현재 표시 중인 글자색과 배경색을 기준으로 계산한다.

## 8. 교육콘텐츠와 피드백 기준

### 8.1 자료 기준

색채용어와 이미지 스케일은 사용자가 지정한 이화여대 색채연구소 자료를 기준으로 검토한다.

실제 자료를 확보한 뒤 다음 사항을 확인한다.

- 정확한 자료명과 발행 정보
- 용어와 분류 체계
- 색 예시와 색값
- 이미지 스케일의 구조와 연결 근거
- 출처 표시와 사용 조건

초기 앱의 I.R.I 표기를 지정 자료와 동일한 근거로 취급하지 않는다.

### 8.2 용어 구분

다음 항목을 구분해 관리한다.

- 일반색명
- 형용색명
- 감성 형용사
- 브랜드 이미지 키워드
- 색의 역할: 주조색·보조색·강조색

검토하지 않은 임시 색 데이터는 표준 자료로 표시하지 않는다.
화면용 근사 색값과 출처가 확인된 색값을 구분한다.

### 8.3 콘텐츠 관리 정보

- 용어와 분류
- 초보자용 설명
- 색 예시와 코드
- 관찰 질문
- 참고 자료와 해당 위치
- 검토 상태

### 8.4 피드백 원칙

- 의도한 이미지와 현재 결과를 스스로 비교하게 한다.
- 색의 이미지는 문화·업종·사용 맥락에 따라 달라질 수 있음을 설명한다.
- 관찰과 수정에 도움이 되는 질문을 제공한다.
- 근거 없는 조화 점수나 자동 합격·불합격 판정을 사용하지 않는다.

글자 대비는 생성형 AI 없이 규칙 기반으로 계산한다.
적용할 접근성 기준과 문구는 공식 자료를 확인한 뒤 정한다.
대비 수치 하나로 전체 가독성이나 접근성이 보장된다고 표현하지 않는다.

## 9. 브랜드 컬러 계획서 작성과 편집

### 9.1 기본 작성 방식

학습자의 입력과 선택값을 검토된 문장 틀에 반영한다.
초기 버전은 생성형 AI API를 사용하지 않는다.

활용 정보:

- 색을 사용할 대상(브랜드명·사업 아이디어 등, `brand.name`)
- 소개와 적용 분야
- 이미지 키워드
- 선택한 색, 색 코드, 역할과 비율
- 4단계 조합 선택 이유(`comboReasonChoice`·`comboReason`)와 색별 선택 이유·활용 위치
- 3단계 대비·관찰(선택형·메모)과 점검 기록

입력하지 않은 사실은 추측해 작성하지 않는다.
보완이 필요한 항목은 ‘작성 필요’로 표시한다.

### 9.2 편집 내용 보존

- 자동 생성 문장과 학습자가 수정한 문장을 구분해 관리한다.
- 색이나 비율이 바뀌면 기존 설명의 재검토가 필요함을 알린다.
- 새 초안을 확인한 뒤 교체할 수 있게 한다.
- 직접 편집한 문장을 재생성 과정에서 즉시 덮어쓰지 않는다.

색·코드·역할·비율의 기준 데이터는 팔레트 상태로 통일한다.
이전 선택을 설명하는 문장이 남아 있으면 해당 항목의 재검토 필요성을 표시한다.

### 9.3 화면과 내보내기

미리보기, 내용 복사, Markdown 다운로드는 같은 최종 데이터를 사용한다.

- Markdown: 계획서의 텍스트, 색 코드, 역할, 비율, 활용 계획
- JSON: 작업을 다시 이어갈 수 있는 전체 상태
- 화면 미리보기: 시각적인 팔레트와 적용 예시를 포함한 결과

Markdown 파일이 화면의 시각적 배치를 그대로 재현한다고 안내하지 않는다.
화면의 「PDF로 저장」은 **브라우저 인쇄**다. 서버 PDF·이미지 파일 생성은 초기 범위에 넣지 않는다. 인쇄물에는 점검 UI와 편집 칸이 빠진다.

## 10. 기술 구조와 작업 보관

### 10.1 기술 방향

- 프런트엔드: Svelte
- 빌드 및 언어 구성: Vite + TypeScript를 기본안으로 사용
- 배포 형태: 정적 웹앱
- 초기 서버 DB: 사용하지 않음
- 초기 계정과 결제: 사용하지 않음
- 초기 생성형 AI API: 사용하지 않음

구체적인 배포 서비스는 별도로 결정한다.

### 10.2 기능 분리

| 영역 | 책임 |
|---|---|
| 교육콘텐츠 | 색채용어, 설명, 활동, 출처 |
| 작업 상태 | 브랜드 정보, 2단계 색별 기록, 비교용 색, 대비·팔레트 관찰 |
| 팔레트 계산 | 비율 조정, 역할 결정, 기준 복귀 |
| 비교 상태 | 기준안 저장과 복원 |
| 미리보기 | 팔레트 적용, 글자색 보정 표시 |
| 계획서 | 템플릿 생성, 항목별 편집, 재검토 표시 |
| 저장·출력 | 브라우저 저장, JSON 입출력, Markdown 출력 |

화면에서 저장 방식이나 계획서 생성 방식에 직접 의존하지 않도록 분리한다.
향후 서버 저장과 AI 작성 기능을 추가할 때 기존 학습 흐름을 활용할 수 있게 한다.

### 10.3 브라우저 자동 저장

현재 작업은 localStorage에 자동 저장한다.

저장 대상:

- 브랜드 정보·1단계 색·톤 선택과 이미지 키워드
- 2단계 `focusPickKey`, `brandPickRecords`, 비교용 색(`interestIds`)과 메모
- 3단계 `compare`(실습 색·기준 스냅샷·선택형 관찰·surround 배경)
- 4단계 `palette`(색·비율·역할·기준 팔레트·`comboReasonChoice` 등)
- 활용 계획과 점검 기록
- 계획서 `fieldEdits`·`sectionEdits`·`decision`·`memo`·재검토 서명
- 현재 단계와 데이터 버전

같은 브라우저에서 작업을 이어갈 수 있게 한다.
브라우저 데이터 삭제나 기기 변경 시 자동으로 복구되지 않는다는 점을 안내한다.
JSON 작업 파일 보관을 제공한다.

저장 실패 시 성공한 것처럼 표시하지 않고 작업 파일 내보내기를 안내한다.

### 10.4 기존 작업 호환

- JSON·localStorage 식별자는 `kind: 'color-plan'`(컬러플랜)이다. 이전 `my-brand-color-canvas` 파일·브라우저 저장은 불러온 뒤 `color-plan`으로 정규화한다.
- 저장 데이터의 버전을 관리한다.
- 새 필드가 없는 기존 파일은 기본값을 적용해 읽는다.
- 기존 브랜드 정보, 팔레트, 이유와 계획서 문장을 보존한다.
- JSON 불러오기 전 구조와 값을 검사한다.
- 지원하지 않는 파일이나 손상된 파일은 이유를 안내한다.
- 불러오기 실패로 현재 작업을 지우지 않는다.
- 기존 문장을 항목별 편집 구조로 옮기기 어려우면 원문을 보존한다.
- 데이터 이전 과정에서 작업을 조용히 초기화하지 않는다.

## 11. 구현 순서

기존 초안 서비스를 다음 순서로 개선한다.

| 순서 | 작업 | 핵심 결과 |
|---|---|---|
| 1 | 팔레트 조절과 미리보기 배치 개선 | 조절과 결과 확인이 한 흐름으로 연결됨 |
| 2 | 기준안·현재안 비교 | 실제 화면을 보며 수정 전후를 설명할 수 있음 |

| 4 | 초기 입력과 반복 작성 축소 | 실습 시작과 기록 부담이 줄어듦 |
| 5 | 적용 예시와 보정 안내 개선 | 사용 위치와 보정 결과를 구분할 수 있음 |
| 6 | 시작 화면의 완성 예시 | 만들 결과를 예상할 수 있음 |
| 7 | 학습 활동과 전체 가독성 정리 | 관찰 목적과 다음 행동이 명확해짐 |
| — | 2단계 「내 색 이해하기」 (활동 1·2, 이중 게이지·톤 비교, 레거시 필드 호환) | **구현 반영** (2026-10-23) |

색채 자료 검토는 관련 콘텐츠 구현과 함께 진행한다.

## 12. 초기 서비스 완료 기준

### 학습 경험

- [ ] 시작 화면에서 무엇을 만들게 되는지 알 수 있다.
- [ ] 긴 소개를 작성하지 않고도 색 실습을 시작할 수 있다.
- [ ] 색과 비율을 조절하면서 결과를 확인할 수 있다.
- [ ] 기준안과 현재안을 함께 보며 차이를 설명할 수 있다.
- [ ] 선택 이유를 단계마다 반복 입력하지 않는다.
- [ ] 의도한 이미지, 글자 보임, 색의 활용 위치를 점검할 수 있다.

### 기능 일관성

- [ ] 비율의 표시 합계가 100%로 유지된다.
- [ ] 동률과 미사용 색을 확정된 규칙으로 처리한다.
- [ ] 역할이 바뀌어도 색별 기록과 카드 위치가 유지된다.
- [ ] 모든 화면과 출력에서 역할·색 코드·비율이 일치한다.
- [ ] 현재안을 변경해도 기준안이 바뀌지 않는다.
- [ ] 기준안 복원 시 관련 없는 기록을 유지한다.
- [ ] 선택한 색과 보정한 글자색을 구분할 수 있다.
- [ ] (후속) 2단계 또는 별도 화면에 「다른 색 살펴보기」 보조 탭을 다시 넣을 경우, 탭과 예시 콘텐츠가 일치해야 한다.
- [x] 1단계 선택 색이 2단계에 표시되고, 색별 기록이 pick 키에 맞게 보존된다.
- [x] 2단계 활동 2에서 1단계 색 vs 비교 후 선택을 이중 게이지로 확인하고, 미선택·부분 완료 상태로도 다음 단계 이동이 가능하다.
- [x] 3단계 실습 색(`compare`)과 4단계 팔레트(`palette`)가 분리된다.
- [x] 3·4단계에서 기준안 저장·복원과 예시/비율 초기화가 구분된다.
- [x] 4단계 미리보기에 사용자 브랜드명이 반영되고, 글자색 보정 여부를 구분할 수 있다.
- [x] 역할 라벨은 슬롯 % 구간(주 51~70, 보 11~50, 강 1~10, 70% 초과는 보조)을 따른다.
- [x] 5단계 목업은 분야와 관계없이 `mokup-all.svg` 한 장이고, 화면 활동은 이미지 확인·활용 계획 2개다.
- [x] 6단계 화면은 점검 → 시각 계획서 → 브라우저 인쇄이며, 인쇄본에서 점검·편집 UI가 빠진다.

### 결과물과 보관

- [ ] 계획서를 시각적으로 확인하고 설명을 항목별로 편집할 수 있다.
- [ ] 새 초안 생성 시 직접 편집한 내용을 보존한다.
- [ ] 화면과 내보내기의 최종 정보가 일치한다.
- [ ] 새로고침 후 작업을 이어갈 수 있다.
- [ ] JSON 내보내기와 불러오기로 작업을 복원할 수 있다.
- [ ] 기존 작업 파일의 내용을 유지한다.
- [ ] 모바일과 키보드로 주요 실습을 수행할 수 있다.

완료 판단에는 실제 초보 학습자의 사용 확인을 포함한다.
학습자가 색을 선택하고 수정한 이유를 설명할 수 있는지 확인한다.

## 13. 후속 확장

초기 서비스의 학습 흐름과 결과물 작성 기능을 완성한 뒤 확장한다.

### 13.1 고급·유료 AI 콘텐츠

업종, 주요 고객, 브랜드 의도와 매체별 요구를 반영해
설명과 활용 방안을 구체화하는 기능을 검토한다.

예:

- 매장·패키지·SNS의 색 적용 방안
- 고객과 브랜드 의도를 반영한 설명
- 같은 팔레트의 매체별 활용 제안
- 대안 비교와 계획서 보완

기본 서비스의 학습 목표와 결과물 완성 기능은 유지한다.

### 13.2 AI 도입 원칙

- 기획서 생성이나 보완 요청 시 호출한다.
- 게이지 조작마다 호출하지 않는다.
- 학습자가 선택한 색과 비율을 임의로 바꾸지 않는다.
- 생성 결과는 검토 가능한 제안으로 제공한다.
- 호출 실패 시 기본 템플릿을 사용할 수 있게 한다.
- API 비밀키는 서버에서 관리한다.

### 13.3 확장 순서

1. 기본 교육 웹앱의 사용성과 결과물 품질 확인
2. 고급 수강생 대상 AI 기능 시범 제공
3. 생성 결과의 유용성, 비용과 수정 요구 확인
4. 운영에 필요한 DB·계정·결제 도입
5. 가격과 제공량 등 상품 정책 결정

초기 화면에는 아직 사용할 수 없는 유료 기능이나 결제 흐름을 필수 단계로 넣지 않는다.
